Data Structures

There are countless data structures that are all important for programmers to learn,so I thought it might be helpful to have some visualizations for different data structures to make it easier to visualize many of them. I don't have many so far, but I plan to keep adding more, both because I think it will be helpful to have visualizations of more data structures, and also that it's kinda fun to make them. Also, there isn't really a specific correct way to illustrate the data structures, so this is just how I thought would illustrate them best. Here are the different visualizations I have made so far:

  • Binary Search Tree
  • Heap
  • Stack
  • Queue
  • Map With Bucket Hashing

Binary Search Tree

A Binary Search Tree is a type of binary tree (each node has up to two children) where every node in the left subtree of a node is less than it, and every node in its right subtree is greater than it. Binary Search Trees are one of the most useful data structures, and can be a good data structure to use in basically any context. The runtime of most of their main operations (insert, delete, lookup, etc.) depend on the height of the tree, so one of the most important aspects of using them is ensuring that it remains pretty balanced. Because of this, there are different types of Binary Search Trees that have added rules that maintain balance in the tree as you change them, such as Red Black Trees and AVL Trees.

I first made this tool initially because I wanted to have a tool for visualizing rotations for Binary Search Trees. Rotations can be really useful for maintaining balance, as rotations are constant time operations. Rotations can be a little confusing to understand, so hopefully this visualization clears up any confusion you might have on how they work.

Heap

A Heap is also a type of binary tree. Heaps are very useful for whenever you want to repeatedly get the max or min. The one I created is an example of a max heap, though I will eventually add an option to either use a min heap or a max heap. I think the data structure seems a bit confusing, but the operations aren't too complex once you understand the premise of it. The main aspects of the heap is that the heap is partially complete and that you sift up and down to ensure that each node is greater than its children. The use case of heaps are pretty specific, though they are really efficient for that use case, so it's a great idea to use them if the opportunity arises.

Stack

I wanted to add some visualizations for some more basic data structures as well, and a stack was probably the simplest. You can maybe imagine stacks through real examples, but you essentially just add elements to the top of the stack, and remove from the top of the stack. Stacks can be pretty useful whenever you want to get the reverse of something, as you remove the elements in the opposite order that you add them.

Queue

Queues are pretty similar in complexity to stacks, though they generally have different applications. The simple way to remember how queues work is "first in first out", meaning that you add to one end of the queue, and remove from the other end of the queue. So they can be useful if you want to repeat some string of characters

Map With Bucket Hashing

Hash maps are one of the most useful data structures that you can use, as they have constant time operations for insert, delete, and get. You can't use them in every context, though because of their incredibly fast running time, you probably should use them whenever possible. There are different kinds of hash maps, the main ones that you'll look at use either bucket hashing or chained hashing. This one here uses bucket hashing, where it stores elements in buckets based on the hash function. Each of the buckets contains a list or some other data structure to hold elements. The one that I made essentially uses a linked list. One of the challenges that come with hash maps is having a good hash function. Many times, the hashing is done for you, so you don't have to worry about it, but if you're creating your own, you'll have to deal with this issue. The goal with your hash function is to have elements evenly be distributed across the buckets, though you also want the hash function to take constant time.
